China A-share factor timing research

Open experiments/China_A_Share_Final_Factor_Timing.ipynb. Its saved outputs include the full main experiment and four figures.

We use Python 3.12 and the versions in requirements-research.txt. Create a Python environment and install that file:
python -m pip install -r requirements-research.txt

Run every notebook cell in order. From the project folder, the same execution is available with:
python review_support/run_final_notebook.py

The notebook reads the saved files under inputs/china_factor_100 and inputs/china_benchmark/market_calendar.csv. It also reads the earlier results/china_factor_timing_m6/predictions_all.csv to check that the main forecasts reproduce M6. The audit also needs that folder's performance.csv. The export needs its input_comparison_metrics.csv and experiments/China_A_Share_Long_Short_Factor_Timing_M6.ipynb. These companion files are included in the supporting ZIP. It does not need an API key, website login or MySQL connection. Keep the folder structure when extracting the ZIP.

The research run writes results/china_factor_timing_final. It takes several minutes on the recorded computer. Every model has its own cell. The main seed is 42; other seeds are 7, 21, 84 and 123. Deep models use a maximum of 100 epochs with early stopping. A failed model or missing required period stops execution. Warnings are saved for review.

After running, verify the calculations:
python review_support/audit_final_experiment.py

After checking the results, regenerate the simple summaries and website files:
python review_support/export_final_research.py

The exported prose describes the recorded experiment. If inputs or design change, update the written interpretation and plan as part of a new research version. The historical M6 comparison and the six-month selector are separate results. The financial statements may include later revisions, and historical short borrowing is assumed.

Large shadow ledgers, seed ledgers and training logs are generated by the notebook. They are included in the full supporting ZIP but are not stored as separate large Git files. Main results, all forecasts, selection scores, checks and website data are kept in Git. The available notebook inventory is not a complete count of every earlier research attempt. The ZIP includes the final and M6 notebooks. If the export runs from that smaller package, it records only the notebooks present there.

The application uses Django. The final results page reads dashboard/china_final_results. It does not train models during a web request. The earlier personal portfolio is a separate long-only research view.
